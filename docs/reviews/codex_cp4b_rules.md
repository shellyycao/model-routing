# Codex CP4b — workflow cost rules checkpoint

**Status: rules drafted; computation not started.** `docs/POSTHOC_WORKFLOW_COST_RULES.md` now fixes the offline Part B/C workflow-cost analysis before any per-path or per-model outcomes are aggregated. The rules use only the verified A/B/C regional prices in `configs/models.yaml` and define executed cost as input/output usage for every API attempt actually made, including failed attempts and retries. Parse-child records cannot be double-counted; validation failures retain their call cost; blocked or not-run stages with no invocation are explicit `not_incurred`; and missing usage is never $0. Unknown failed-attempt usage must use the experiment's recorded/reconstructable conservative reservation or make the run total `not estimable`.

The primary tables will report project/path and separately labeled pooled results with `n_runs`, non-void and feasible denominators, cost completeness, mean cost per run, and total spend divided by feasible completions. A zero-feasible group is fixed as `not estimable`, and every `n=1` row is tagged `single-run evidence`. Project-level and pooled Pareto frontiers use mean executed run cost versus frozen feasibility rate, excluding incomplete points with reasons.

The Router sensitivity and counterfactual sections are explicitly separated from executed cost. Their dollar quantity is labeled **post-hoc conversion of the Router's token predictions**; the frozen Router never predicted dollars. The cost-first view preserves the frozen candidates, constraints and tie tolerance, while the counterfactual check compares three-way cost direction only when both converted token estimates and referenced executed costs are estimable. No raw record, trace, prediction, Router output, or validator was changed; no model/network call or result aggregation was performed.
