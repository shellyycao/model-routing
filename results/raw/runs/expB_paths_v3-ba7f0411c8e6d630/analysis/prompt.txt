## Original objective
Clean and join a support-ticket export with an agent roster, analyse cost, speed, reopening, satisfaction and agent concentration, then report verified findings.

## Handoff from the previous stage
Completed stages: cleaning
Validation status of previous stages: {"cleaning": "passed"}
Cleaning logic reported by the cleaning stage:
The script reads tickets.csv and agents.csv as plain text, strips whitespace and treats common placeholders (empty, NA, N/A, null, None, -) as missing. It removes duplicate ticket_id rows and duplicate agent_id rows (after upper‑casing agent IDs). Agent records are normalised: team names are mapped to Alpha/Beta/Gamma, regions to East/West, and hourly_cost strings are cleaned of '$', 'USD' and commas and converted to a positive float. Invalid agent rows are discarded. Ticket records are upper‑cased for agent_id and inner‑joined to the cleaned roster, dropping tickets without a matching agent. Channels are mapped to the canonical set (email, chat, phone) and invalid ones are removed. Resolution minutes are stripped of the words "min"/"minutes", parsed as integers, and kept only if between 1 and 480. Satisfaction scores are parsed as integers 1‑5; invalid or missing values become empty (NaN) but the row stays. The reopened flag is normalised to 1/0, dropping rows with unrecognised values. Labor cost is calculated as (resolution_minutes/60) * hourly_cost and rounded to two decimals. Finally, the required columns are ordered, rows sorted by ticket_id, and the cleaned CSV is written. A JSON summary records row counts and how many rows were removed at each step.

## Analysis questions and the metric_keys each must produce
- q1: Overall: number of tickets -> ticket_count; mean resolution_minutes -> mean_resolution_minutes; sum of labor_cost -> total_labor_cost.
  metric_keys: ticket_count, mean_resolution_minutes, total_labor_cost
- q2: Team comparison: total labor_cost for Alpha, Beta and Gamma -> labor_cost_alpha, labor_cost_beta, labor_cost_gamma.
  metric_keys: labor_cost_alpha, labor_cost_beta, labor_cost_gamma
- q3: Channel comparison: mean resolution_minutes by channel -> resolution_email, resolution_chat, resolution_phone.
  metric_keys: resolution_email, resolution_chat, resolution_phone
- q4: Reopening change: reopened percentage for email and chat -> reopen_rate_email_pct, reopen_rate_chat_pct; (email rate - chat rate) / chat rate * 100 -> email_vs_chat_reopen_change_pct.
  metric_keys: reopen_rate_email_pct, reopen_rate_chat_pct, email_vs_chat_reopen_change_pct
- q5: High-cost low-satisfaction segment: tickets with labor_cost >= 100 and a non-missing satisfaction_score <= 2 -> count and reopened percentage as high_cost_low_sat_count and high_cost_low_sat_reopen_pct.
  metric_keys: high_cost_low_sat_count, high_cost_low_sat_reopen_pct
- q6: Distribution: median and sample standard deviation of resolution_minutes -> resolution_median, resolution_std; mean non-missing satisfaction_score -> satisfaction_mean; missing satisfaction count -> satisfaction_missing_count.
  metric_keys: resolution_median, resolution_std, satisfaction_mean, satisfaction_missing_count
- q7: Agent concentration (derived step): distinct agent_id count -> unique_agent_count; largest ticket count for one agent -> top_agent_ticket_count; top_agent_ticket_count / ticket_count * 100 -> top_agent_ticket_share_pct.
  metric_keys: unique_agent_count, top_agent_ticket_count, top_agent_ticket_share_pct

All required metric_keys: ticket_count, mean_resolution_minutes, total_labor_cost, labor_cost_alpha, labor_cost_beta, labor_cost_gamma, resolution_email, resolution_chat, resolution_phone, reopen_rate_email_pct, reopen_rate_chat_pct, email_vs_chat_reopen_change_pct, high_cost_low_sat_count, high_cost_low_sat_reopen_pct, resolution_median, resolution_std, satisfaction_mean, satisfaction_missing_count, unique_agent_count, top_agent_ticket_count, top_agent_ticket_share_pct
